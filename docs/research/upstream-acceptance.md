# What would upstream SumatraPDF need before it accepted the Page Turn?

Research for [#46](https://github.com/futureradius/sumatrapdf-skeuomorph/issues/46) (map [#36](https://github.com/futureradius/sumatrapdf-skeuomorph/issues/36)).
A thought experiment: nothing was posted upstream. Measured on 2026-11-16 against
`upstream/master` at `b1a8e2257` (2026-11-10) and our `scrolling` at `9bab0cc6c`.

## Answer

As one pull request of today's branch: unlikely. The maintainer (Krzysztof
Kowalczyk, `kjk`) does merge large outside features, Windows-only ones and
animations included, but he has said he prefers an issue with a description
and sketches over a big PR, wants separate PRs for separate features, and our
change is about 2.5 times the largest feature PR he merged this year.

The realistic path: an issue first, with a video and a test build, then a
smaller, off-by-default version split into several PRs and stripped of the
fork's merge-avoidance scaffolding. Even then he may well rewrite it himself,
as he did with the Windows 11 print dialog.

## 1. Contributing rules

- The developer page asks for the standard GitHub flow and recommends
  discussing "a significant addition" in the issue tracker first; it does not
  require it. It also says not to edit the Visual Studio solution directly
  (it is generated by premake).
  [Contribute to SumatraPDF](https://www.sumatrapdfreader.org/docs/Contribute-to-SumatraPDF)
- There is no `CONTRIBUTING.md`; `readme.md` links to that page. The repo's
  `agents.md` is the de facto rulebook (coding, commits, tests, docs). Upstream
  expects AI-assisted work: 3,331 of the 3,390 upstream commits in the last 90
  days carry a `prompt:` line (`git log --since=2026-08-16 upstream/master`).
- On a large outside PR (TTS + library, #5836) kjk wrote: "should be separate
  PRs" and "Frankly, I prefer an issue with detailed description of how such
  feature should work, ui sketches / pointers to how other apps implement
  this than a PR."
  [sumatrapdf#5836](https://github.com/sumatrapdfreader/sumatrapdf/pull/5836)

## 3. Stance on animation, eye candy and weight

- **No recorded stance on page-turn animation.** No upstream issue asks for
  one (searches "page flip", "page curl", "flip animation", "flipbook" in
  sumatrapdfreader/sumatrapdf). The forum has a "page flip sound" request but
  no kjk reply found ([forum](https://forum.sumatrapdfreader.org/t/keyboard-page-flip-sound/4433)).
- **He has shipped animation, on by default, with an opt-out.** Smooth
  scrolling started as an opt-in experiment in 2022 ("I'm not sure if that's
  an improvement so please test and comment",
  [discussion #2397](https://github.com/sumatrapdfreader/sumatrapdf/discussions/2397)).
  In July 2026 he made it always on, then restored the `SmoothScroll` setting
  a day later with default `true` (`e0db776af`, `15a48380c`). When users said
  it made them dizzy and was slow on old PCs, his answer was "set
  `SmoothScroll` advanced setting to `false`"
  ([#5839](https://github.com/sumatrapdfreader/sumatrapdf/issues/5839)).
- **GPU drawing is already in.** Upstream switched to Direct2D by default in
  August 2026 (`391d4e811`) and the print dialog uses D3D.
- **Weight.** The long-time supporter who answered our [#24](https://github.com/futureradius/sumatrapdf-skeuomorph/issues/24)
  describes the old ethos as "lightest by all means", loosened since theming,
  and guesses kjk "would probably accept a well AI prompted flipping action".
  A user in #5839 calls lightness "part of Sumatra's appeal". kjk himself
  has added large features this year (AI chat, OFD, Microsoft Reader `.lit`,
  thumbnails sidebar). He prefers user configuration over code changes where
  possible: "we now allow customizing the toolbar and therefore we won't be
  changing toolbar in the code" ([#5208](https://github.com/sumatrapdfreader/sumatrapdf/issues/5208)).

## 4. Repo rules the feature would meet

- **Windows-only is allowed.** `agents.md`: "Retain Windows-only features on
  Windows until they can be ported." The Windows 11 print dialog is a recent
  Windows-only precedent.
- **But ng is where upstream is heading.** 1,032 of 3,390 upstream commits in
  the last 90 days touch `src/ng`. ng must "match the original Windows UI" and
  uses GPUI everywhere, which has no shader API (`ext/gpui/gpui.h` has no
  occurrence of "shader"). A port would need framework work in kjk's
  `gpui-kit-cpp`, so the Curl would stay a Windows-only island. Our
  `hide-ng` hook already hides the command in ng; `cmd/ng-gen-settings.ts`
  keeps its own settings list, which we did not touch.
- **Windows 7.** Upstream still builds for Windows 7 (`premake5.lua`:
  `WINVER=0x0601`). DirectComposition needs Windows 8; our code loads
  `dcomp.dll` and `d3d11.dll` at run time and has a failure path, which would
  need testing on Windows 7 and ARM64.
- **Settings.** Defined in `cmd/gen-settings.ts`, generated code, docs
  regenerated. Ours: `SkeuomorphPageTurn` (default `true`) and
  `PageTurnDuration` (700 ms), marked `.ver("3.7")`.
- **Commands.** Added at the very end of `cmd/gen-commands.ts` (ours is),
  documented in `www/docs/Commands.md` and under **New commands** in
  `Version-history.md` in the website repo.
- **Translations.** Menu text goes through `TrN(...)`; strings reach
  translators via apptranslator.org, uploaded by the maintainer
  (`TRANS_UPLOAD_SECRET`). A contributor only adds the English string. Ours
  adds one: "Skeuomorph Page Turn".
- **Tests.** Upstream wants `tests/issue-<n>.ts` registered in
  `tests/run-almost-all.ts` (or `ad-hoc-*.ts`), runnable on GitHub's daily CI
  runner.
- **Tooling.** Build scripts are bun TypeScript under `cmd/`; project files
  are generated by premake.

## 6. Upstream churn and what it has cost us

- **Rate:** 7,762 commits in the last 365 days (~21/day), 3,390 in 90 days,
  543 in 30. 7,679 of the year's commits (99%) are kjk's.
- **Our merges:** none yet. The branch forked on 2026-11-09; upstream is 6
  commits ahead, one of them a 74-file refactor ("Deepen modules and narrow
  interfaces under src/", `119ffebb9`).
- **Trial merge** (`git merge-tree --write-tree origin/scrolling upstream/master`,
  nothing written to a branch): 3 conflicts, all in the command list
  (`cmd/gen-commands.ts`, `src/shared/Commands.cpp/.h`), because upstream's
  "Save Trimmed Pages As" also appended a command. Every hook in `Canvas.cpp`,
  `SumatraPDF.cpp`, `DisplayModel.cpp` and the rest merged cleanly. ADR 0003
  predicted exactly this: generated files conflict, fixed by re-running the
  generator.
- At ~21 commits a day, a week behind is ~150 commits; the cost so far is
  small, but no long gap has been tested yet.

## 7. Work list before an upstream PR

1. **Issue first.** Description, short video, link to a test build; ask
   whether he wants it at all and in what shape. (Per #5836.)
2. **Off by default.** `SkeuomorphPageTurn` default `false`, like smooth
   scrolling began. A plainer menu name than "Skeuomorph", e.g. "Page Turn
   Animation".
3. **Split.** Separate PRs: the two callbacks/hooks; Page Edges (~330 lines);
   the Curl (D3D11 + DirectComposition); Rough Pages. Each must stand alone.
4. **Drop fork scaffolding.** `// skeuomorph: hook` tags, `docs/skeuomorph-hooks.md`,
   ADRs, glossary and `agents.md` edits; `FlashRecorder` out of shipping code
   (or behind a debug flag); `compile-shaders.ps1` / `run-gen-code.bat`
   replaced by `cmd/*.ts` or folded into the build. Upstream does not need
   merge-avoidance seams and may prefer the code inline.
5. **Fit the code to upstream.** `agents.md` style (clang-format, function
   names under 30 characters, enums instead of bool parameters, comments in
   `.cpp`), project files regenerated by premake. Expect the question whether
   the Curl can share upstream's Direct2D/D3D device instead of its own.
6. **Platforms.** Verify the fallback on Windows 7 (no DirectComposition),
   ARM64, and a GPU-less CI runner. Confirm ng ignores and preserves the two
   new settings.
7. **Tests.** Turn the 11 `tests/skeuomorph-*.ts` scripts into
   `issue-<n>.ts` / `ad-hoc-*.ts` registered the upstream way; keep
   `PageTurnLogic_ut.cpp` in `-unit-tests`.
8. **Docs** in the website repo: `Commands.md`, regenerated settings page,
   `Version-history.md` (feature bullet + **New commands**), and a feature
   page per `docs/writing-docs.md`.
9. **Measure** release-build size and idle memory against clean upstream, and
   CPU/GPU cost per turn on an old PC (the #5839 complaint).
10. **ng.** Say plainly it is Windows-only; a port needs GPUI shader support
    upstream does not have.
