# Research: adding settings and View-menu switches

Answers [#7](https://github.com/futureradius/sumatrapdf-skeuomorph/issues/7). Classic Windows app only (`src/ng/` ignored). All citations are `file:line` at commit `d66646860`. No source code was changed.

## Plain answer

Every setting is written once, in a TypeScript list (`cmd/gen-settings.ts`), together with its default value. A script reads that list and rewrites two C++ files (`src/Settings.h`, `src/Settings.cpp`). Those files must never be edited by hand. The script needs the program **bun**, which is **not installed** on this machine. A View-menu checkmark is a *command* (also written in a generated list, `cmd/gen-commands.ts`) plus three small hand-written pieces: the menu entry, the code that sets the checkmark, and the code that flips the setting when clicked. The closest existing model is **Highlight Form Fields**: an on-by-default switch in the View menu that is remembered between sessions.

## 1. Where settings are defined, and what is generated

| What | Where | Hand-edit? |
|---|---|---|
| Setting definitions (name, type, default, comment) | `cmd/gen-settings.ts`, array `globalPrefs` starting at `cmd/gen-settings.ts:1454` | **Yes**: the only place to edit |
| Field order inside the C++ struct | `globalPrefsLayout`, `cmd/gen-settings.ts:2454`; used for sorting at `cmd/gen-settings.ts:2793-2797` | Yes (add the new name next to similar ones) |
| C++ struct `Settings` | `src/Settings.h` (header line 1: `// !!!!! This file is auto-generated by cmd/gen-settings.ts`) | **No**: generated |
| Load/save metadata incl. defaults | `src/Settings.cpp` (`gSettingsFields`, `gSettingsInfo` at `src/Settings.cpp:1278`) | **No**: generated |

- The generator writes both files at `cmd/gen-settings.ts:3551-3554`. It uses the relative path `src/...`, so it must be run **from the repo root**.
- It also tries to update the website's settings docs, and quietly skips that when the website checkout is missing (`cmd/gen-settings.ts:3563-3564`). That's harmless for this fork.
- The classic build (`vs2022\SumatraPDF.sln`, `cmd/build.ts`) does **not** run the generator. The generated files are committed to git (`git ls-files` lists `src/Settings.h`, `src/Settings.cpp`, `src/shared/Commands.h`, `src/shared/Commands.cpp`). After editing the `.ts` list, you run the generator yourself, then build.
- Repo rule: `agents.md:332-337` (add to `cmd/gen-settings.ts`, then run `bun cmd/gen-code.ts` or `bun cmd/gen-settings.ts`).

### Field types available
`Bool`, `Int`, `Float`, `Str`, `Color` (`cmd/gen-settings.ts:108-113`). Chainable modifiers (`cmd/gen-settings.ts:56-104`) are `.ver()` (doc version label), `.internal()` (saved but hidden from the Advanced Settings dialog), `.notSaved()`, `.enum([...])` and others.

### Where defaults live
The third argument of `field(...)` is the default. The generator copies it into the metadata table, for example:

- `cmd/gen-settings.ts:1942-1947` `field("SmoothScroll", Bool, true, ...)` → `src/Settings.cpp:1155` `{offsetof(Settings, smoothScroll), SettingType::Bool, true}`
- `cmd/gen-settings.ts:2010-2015` `field("ReadingAutoScrollSpeed", Float, 40, ...)` → `src/Settings.cpp:1165` `{..., SettingType::Float, (intptr_t)"40"}`

When the settings file has no value for a key, the loader uses that default: Bool at `src/base/SettingsUtil.cpp:322-330`, Int at `:332-339`, Float at `:341-345`. Saving writes every Bool/Int/Float value (`src/base/SettingsUtil.cpp:239-247`). So the new keys appear in `SumatraPDF-settings.txt` after the first save.

## 2. The number setting (Curl speed) in Advanced Settings

Adding the `field(...)` is enough for it to show up in **Settings → Advanced Settings...** (`src/shared/MenuDefs.cpp:579-580`, command `CmdAdvancedSettings`). That dialog is "driven by the settings metadata (gSettingsInfo)", so it lists every non-internal setting automatically and edits numbers in place (`src/AdvancedSettingsDialog.cpp:4-9`, Int/Float handling at `:699`, `:759`).

Models to copy:

- **Float speed:** `ReadingAutoScrollSpeed`, `cmd/gen-settings.ts:2010-2015` (default 40, comment states the valid range). Read in code as `gSettings->readingAutoScrollSpeed` and clamped before use (`src/shared/ReadingAutoScrollCommon.cpp:34-53`).
- **Int with fallback:** `ScrollLineAmount`, `cmd/gen-settings.ts:1948-1953`; clamp helper at `src/shared/CanvasCommon.cpp:63-65`.
- **Clamp on load:** `SaveMemory` is clamped with `setMinMax` in `ApplySettingsToOpenWindows`, at `src/shared/AppSettings.cpp:420-423`.

The settings file is hand-editable text, so out-of-range values must be clamped where the value is read.

## 3. The on/off switch with a View-menu checkmark

### The model to copy: Highlight Form Fields
It is a global `Bool` setting, on by default, with a View-menu checkmark:

1. **Setting**: `cmd/gen-settings.ts:1815-1820` `field("HighlightFormFields", Bool, true, "...").ver("3.7")`, and its name in `globalPrefsLayout` at `cmd/gen-settings.ts:2577`. Generated as `src/Settings.h:1327` `bool highlightFormFields;` and `src/Settings.cpp:1134`.
2. **Command**: `cmd/gen-commands.ts:295` `"CmdToggleHighlightFormFields", "Toggle Highlight Form Fields",` is generated into `src/shared/Commands.h:288` and `src/shared/Commands.cpp:294`. The second string is the command-palette name.
3. **Menu entry**: `src/shared/MenuDefs.cpp:351-354` `{ TrN("&Highlight Form Fields"), CmdToggleHighlightFormFields },` inside `menuDefView[]` (`src/shared/MenuDefs.cpp:229`).
4. **Checkmark**: `src/Menu.cpp:956` `MenuSetChecked(win->menu, CmdToggleHighlightFormFields, gSettings->highlightFormFields);` inside `MenuUpdateStateForWindow` (`src/Menu.cpp:886`). That runs each time a menu opens: `WM_INITMENUPOPUP` (`src/SumatraPDF.cpp:14156-14161`) → `UpdateAppMenu` (`src/Menu.cpp:1457`) → `MenuUpdateStateForWindow` (`src/Menu.cpp:1482`).
5. **Click handler**: `src/SumatraPDF.cpp:12092-12097` flips `gSettings->highlightFormFields` and redraws all windows.
6. **Optional extras:**
   - On/off state shown in the command palette: `src/CommandPalette.cpp:1382-1385`.
   - Hide the command where it makes no sense: `src/shared/CommandAvailability.cpp:638`. For the page turn, this could hide it in Continuous View or non-paged documents.

### Saving it right away
Highlight Form Fields relies on the save at exit (`src/SumatraPDF.cpp:4785-4786` calls `ScheduleSaveSettings(); FlushScheduledSaveSettings();`). `CmdToggleDisableLinks` is a slightly better model: it also calls `ScheduleSaveSettings()` straight after the flip, and uses `ShouldToggle(cmd, ...)` so that `[CmdX on]`/`[CmdX off]` shortcuts work (`src/SumatraPDF.cpp:12099-12110`; `ShouldToggle` at `src/shared/SumatraPDFCommon.cpp:1640-1645`; `ScheduleSaveSettings` at `src/shared/AppSettings.cpp:729-739`, which does nothing under `-for-testing`).

To accept that optional on/off argument, the command also needs a line in the hand-written argument table outside the generated block (`src/shared/Commands.cpp:442-453`; the generated block ends at `src/shared/Commands.cpp:393`).

### Adding the command: rules and catch
- Add new commands **at the very end** of `commandsRaw` (last entry today is `CmdAIChatWithCustomAPI`, `cmd/gen-commands.ts:384`; list closes at `:385`). Command ids are assigned by position (`agents.md:343`; `src/shared/Commands.h:379` `CmdLast = 571`).
- Then run `bun cmd/gen-commands.ts` (or `bun cmd/gen-code.ts`), `agents.md:344`.
- There is already a generic `CmdToggleBoolSetting <Name>` that can flip any Bool setting from a keyboard shortcut (`src/SumatraPDF.cpp:10769-10784`). A menu item needs its own plain command id, though, so a dedicated command is still the way to get a View-menu checkmark.

## 4. Running the generator: bun is required and not installed

- All generators are bun scripts. They use `Bun.spawn`, `Bun.which`, `import.meta.dir` and `import.meta.main` (for example `cmd/util.ts:236`, `cmd/util.ts:256`, `cmd/gen-code.ts:442`), so plain Node (v24 is installed) **cannot** run them.
- `bun` is not on PATH and `~/.bun` does not exist on this machine (checked 2026-11-09).
- No npm packages are needed: gen-settings/gen-commands import only `node:fs`, `node:path` and `./util` (`cmd/gen-settings.ts:4-6`, `cmd/gen-commands.ts:1-2`).
- **clang-format catch:** `bun cmd/gen-settings.ts` and `bun cmd/gen-code.ts` run clang-format on the output (`cmd/gen-settings.ts:3555-3558`, `cmd/gen-code.ts:450`). clang-format is installed with VS Build Tools (`...\2022\BuildTools\VC\Tools\Llvm\x64\bin\clang-format.exe`). But the repo's Visual Studio finder only looks in `C:\Program Files\Microsoft Visual Studio\2022\{Community,Professional,Enterprise}` (`cmd/util.ts:19`, `:74-83`) or for `msbuild` on PATH (`cmd/util.ts:43-72`). Build Tools lives under `Program Files (x86)`, so without MSBuild on PATH the run fails with "couldn't find clang-format" (`cmd/util.ts:231-243`) **after** the files have already been written unformatted. Fix: put MSBuild on PATH for that PowerShell window first.

Exact PowerShell 5.1 commands:

```powershell
# one-time: install bun (official installer), then open a NEW PowerShell window
powershell -c "irm bun.sh/install.ps1 | iex"

# each time, from the repo root, after editing cmd\gen-settings.ts / cmd\gen-commands.ts
cd C:\code\sumatrapdf-skeuomorph
$env:PATH = "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\MSBuild\Current\Bin;" + $env:PATH
bun cmd/gen-code.ts
git status
```

Success looks like `Wrote 'src\Settings.h' and 'src\Settings.cpp'` and `gen-code finished in ...s`, with `git status` showing those files and `src/shared/Commands.*` changed. (`winget install --id Oven-sh.Bun` is an alternative installer.)

## 5. Fork and upstream-merge consequences

- **Generated files will conflict on every upstream merge** that touches settings or commands (`src/Settings.*`, `src/shared/Commands.*`, and the `.ts` lists). Resolve the `.ts` lists by hand, then re-run `bun cmd/gen-code.ts` instead of merging generated text. So bun is needed for upstream updates too, not just once.
- **Command id shift:** upstream also appends commands at the end. After a merge our command moves to a new number. Harmless as long as nothing stores the number: shortcuts in the settings file use names, and tests must use `cmdId("Name")` (`agents.md`, "Writing tests").
- **ng sharing:** `src/shared/*` (MenuDefs, Commands, AppSettings, CommandAvailability) is also compiled by SumatraPDF ng, which has its own `src/ng/Settings.h` from `cmd/ng-gen-settings.ts` (`cmd/ng-gen-settings.ts:3536-3537`). Reading `gSettings->skeuomorphPageTurn` inside a `src/shared/` file would break the ng build unless `cmd/ng-gen-settings.ts` gets the same field. `agents.md:336` says to add it to both. Keeping the `gSettings` reads in classic-only files (`src/Menu.cpp`, `src/SumatraPDF.cpp`, new files) avoids that. The menu entry in `src/shared/MenuDefs.cpp` is fine because `Commands.h` is shared (`cmd/ng-gen-commands.ts` just re-exports `gen-commands`).
- Upstream doc rules (`www/docs/Commands.md`, Version-history in `agents.md:345-346`) refer to the separate website repo and don't apply to this personal fork.
- Menu access keys (`&X`) must be unique within the View menu group, which `cmd/check-access-keys.ts` checks (groups marked `//[ ACCESSKEY_GROUP View Menu` at `src/shared/MenuDefs.cpp:228`). New `TrN(...)` labels are simply untranslated (shown in English).

## Minimal touch list for the feature

1. `cmd/gen-settings.ts`: two `field(...)` entries (Bool on by default; Float/Int speed) plus their names in `globalPrefsLayout`.
2. `cmd/gen-commands.ts`: one command at the very end.
3. Run `bun cmd/gen-code.ts` (regenerates `src/Settings.*`, `src/shared/Commands.*`).
4. `src/shared/MenuDefs.cpp`: one `menuDefView` entry.
5. `src/Menu.cpp`: one `MenuSetChecked` line.
6. `src/SumatraPDF.cpp`: one `case` in the command switch (flip, `ScheduleSaveSettings()`, redraw).
7. Optional: `src/shared/Commands.cpp` state arg, `src/CommandPalette.cpp` toggle state, `src/shared/CommandAvailability.cpp` hide rule.
